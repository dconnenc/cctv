# Family Feud bucketing eval

An on-demand **prompt-iteration scorecard** for the AI that groups raw audience
responses into Family Feud answer buckets (`AI::Prompts::FamilyFeudBucketing` →
Gemini, applied in `Experiences::Orchestrator#auto_categorize_family_feud!`).

It exists to answer one question while you tune the prompt: _did this change make
the buckets look more like a real Family Feud board?_ It is **not** a CI gate — it
hits the live Gemini API and reports scores, it never fails a build.

## Running

```bash
rake eval:family_feud                                  # score the production prompt
VARIANTS=production,candidate_example rake eval:family_feud   # A/B two prompts
RUNS=3 JUDGE=false rake eval:family_feud               # cheaper: skip the LLM judge
rake eval:family_feud:baseline                         # refresh baseline.json (do this first)
rake eval:family_feud:generate                         # rebuild fixtures from fixtures_src/
```

Each run prints a scorecard and writes `results/result-<ts>.{json,md}` (gitignored).
Requires `GEMINI_API_KEY`. The default run also prints **Δ vs `baseline.json`** — run
`rake eval:family_feud:baseline` once to establish it, then it travels in git so
prompt-change PRs show their score movement.

Cost is a few hundred Flash calls + a dozen Pro judge calls per variant — cents.

## How it works

Real Family Feud gives us finished **boards** (grouped labels + point counts) but
not the raw 100 responses. So we run it backwards: each fixture takes a real board
and **expands it into synthetic raw responses** (paraphrase variants, proportional
to the point values), shuffles them, and records the known grouping as **gold**.
The model under test sees only the shuffled raw list; we score how well it
reconstructs the board.

- `fixtures_src/*.json` — hand-authored compact sources (question, board, per-label
  variant phrasings, singletons, junk). The creative input.
- `fixtures/*.json` — frozen, generated by `:generate` (deterministic, no API, so
  regenerating is byte-identical). **Do not hand-edit; edit the source and regenerate.**
- `anchor/*.json` — hand-authored real-style fixtures (full schema). A transfer
  check that synthetic conclusions hold on realistic prompts; reported separately.
- `prompts/*.txt` — A/B prompt variants using `{{question}}` / `{{answers}}`.

Determinism is enforced at `temperature: 0` (also now the production default).

## What the metrics mean

**Tier 1 — partition quality (deterministic, leads the loop):**

| metric                                  | reads as                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| `pairwise_f1`                           | overall grouping accuracy                                                          |
| `over_merge` (= 1 − pairwise precision) | **"too close together"** — distinct answers merged into one bucket                 |
| `over_split` (= 1 − pairwise recall)    | one answer fragmented across buckets                                               |
| `homogeneity` / `completeness`          | entropy view of merge (homogeneity↓) vs split (completeness↓)                      |
| `unassigned_recall`                     | **the "Other" failure** — junk/singletons that should be left out but got bucketed |
| `unassigned_precision`                  | real answers wrongly left unbucketed                                               |
| `bucket_count_delta`                    | buckets vs the real board count                                                    |

**Tier 2 — label / board quality:**

- deterministic checks: generic names ("Other", "Misc", "Various"), the 1–4-word
  rule, and near-duplicate names.
- LLM judge (Gemini **2.5 Pro** — a different, stronger model than the Flash under
  test): rates specificity, FF-style, name accuracy, and resemblance to the real
  board (1–5).

The scorecard breaks every metric down **by difficulty dimension** (`paraphrase`,
`near_miss`, `borderline`, `off_topic`, `singleton`) so you can see _where_ a prompt
fails — e.g. fine on paraphrases but over-merging near-miss pairs.

## Adding fixtures

1. Add a board to `fixtures_src/<id>.json` (see existing files for the shape). Tag
   the difficulty dimensions it exercises.
2. `rake eval:family_feud:generate`.
3. Commit the source **and** the generated fixture.

Pure-function tests live in `spec/evals/family_feud_pure_spec.rb` (CI-safe, no API).
